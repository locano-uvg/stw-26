Vite

El bundler moderno para React

¿Por qué Vite y no Webpack?

Un poco de contexto

Antes existía Create React App (CRA)

  • Era la forma "oficial" de iniciar un proyecto React
  • Usaba Webpack + Babel tras bambalinas
  • Empaquetaba todo el proyecto antes de servirlo
  • Deprecado oficialmente en 2025 por el equipo de React

La pregunta importante: ¿qué lo reemplazó y por qué?

¿Qué problema resuelve un bundler?

El navegador no entendía nuestro código

  • JSX, TypeScript, SCSS → el navegador no los ejecuta
  • Históricamente, import / export tampoco funcionaba en el navegador
  • Cientos de archivos pequeños = cientos de requests HTTP

El rol del bundler

  • Transformar: JSX/TS → JavaScript que el navegador entiende
  • Empaquetar: muchos archivos en pocos bundles optimizados
  • Servir en desarrollo: dev server con recarga automática
  • Construir para producción: minificar, tree-shake, optimizar

Dos modos distintos

Dev: rápido, con HMR, sin optimizar

Build: lento, optimizado al máximo, listo para deploy

La gran diferencia entre Webpack y Vite está sobre todo en el modo dev

Webpack tras bambalinas

Estrategia: bundle-first

  1. Lee tu archivo de entrada (ej. index.js)
  2. Sigue todos los import recursivamente
  3. Construye un grafo completo de dependencias
  4. Genera un bundle único (o varios chunks)
  5. Recién ahí levanta el dev server

Diagrama mental

[ archivos del proyecto ]
        ↓
[ grafo completo de deps ]
        ↓
[ bundle empaquetado ]
        ↓
[ servidor lo entrega ]

En proyectos grandes esto puede tardar 10-30 segundos en cada arranque.

Cuando cambias un archivo...

  • Webpack tiene que re-bundlear partes del grafo
  • HMR existe, pero re-procesa más de lo necesario
  • Mientras más crece el proyecto, más lento se siente

Y la configuración...

  • webpack.config.js con loaders, plugins, reglas, alias
  • Babel aparte, ESLint aparte, PostCSS aparte
  • CRA escondía todo esto, pero al "ejectarlo" aparecía el monstruo

Vite tras bambalinas

(Vite = "rápido" en francés)

La idea clave: ESM nativo

Hoy todos los navegadores modernos entienden import y export de forma nativa.

Vite aprovecha esto: en desarrollo no bundlea.

¿Cómo funciona en dev?

  1. Vite levanta un servidor en menos de 1 segundo
  2. El navegador pide main.jsx
  3. Vite lo transforma al vuelo y lo devuelve
  4. Ese archivo importa otros → el navegador los pide uno por uno
  5. Vite solo procesa lo que el navegador realmente necesita

Diagrama mental

[ navegador ]  ──pide module.js──→  [ Vite ]
[ navegador ]  ←─transformado─────  [ Vite ]

Solo se transforma lo que se pide.
No hay grafo completo. No hay bundle.

Pre-bundling con esbuild

  • Las dependencias de node_modules sí se pre-empacan
  • Lo hace esbuild, escrito en Go
  • 10-100x más rápido que herramientas en JavaScript
  • Se hace una sola vez y se cachea

HMR granular

  • Cambias un componente → Vite invalida solo ese módulo
  • El estado de la app se preserva
  • Se siente instantáneo, sin importar el tamaño del proyecto

¿Y para producción?

  • Vite usa Rollup para el build final
  • Mejor tree-shaking que Webpack
  • Output más pequeño y limpio
  • npm run build → carpeta /dist lista para deploy

Webpack vs Vite

Aspecto Webpack Vite
Estrategia en dev Bundle completo antes de servir ESM nativo, transforma bajo demanda
Tiempo de arranque 5-30s en proyectos grandes < 1s
HMR Re-bundle parcial Módulo aislado, instantáneo
Pre-bundle deps Babel / JS esbuild (Go)
Build producción Webpack Rollup
Configuración Extensa, muchos plugins Mínima, defaults sensatos

¿Por qué les importa esto a ustedes?

Ciclo de feedback

Builds más rápidos = ven el cambio antes = aprenden y prototipan más rápido.

Lo que en Webpack tardaba 10s, en Vite es instantáneo. Multiplicado por cientos de cambios al día.

Menos config, más código

No pelean con webpack.config.js. Se enfocan en aprender React, no en domar el bundler.

Es el estándar actual

  • Vite lo recomienda hoy la documentación oficial de React
  • Astro, SvelteKit, Nuxt usan Vite por debajo
  • Next.js y Remix usan herramientas también basadas en ESM
  • Aprender Vite = entender hacia dónde va el ecosistema

Creando un proyecto con Vite

Comandos

npm create vite@latest mi-proyecto -- --template react
cd mi-proyecto
npm install
npm run dev
  • Listo en segundos
  • Configuración mínima inicial
  • Estructura moderna y limpia

Scripts disponibles

  • npm run dev — servidor de desarrollo
    • ESM nativo + transformación bajo demanda
    • HMR instantáneo
  • npm run build — build de producción
    • Rollup optimiza el bundle final
    • Genera /dist
  • npm run preview — sirve el build localmente para probar

Actividad en clase

  1. Crear un proyecto con Vite + React
  2. Abrir las DevTools → Network y ver cómo el navegador pide cada módulo individualmente en dev
  3. Modificar un componente y observar el HMR instantáneo
  4. Ejecutar npm run build y explorar la carpeta /dist
  5. Comparar: cantidad de archivos en dev vs en build

Conclusión

Vite es el estándar moderno para React.

No es magia: es el resultado de aprovechar ESM nativo y herramientas más rápidas (esbuild, Rollup) en vez de bundlear todo desde el principio.

Menos configuración, más productividad.
