00
¿Qué son los Hooks?
Funciones especiales que permiten usar estado y ciclo de vida dentro de componentes funcionales. Reemplazan completamente a los componentes de clase.
Idea clave

Antes, los componentes funcionales eran "tontos": solo recibían props y devolvían JSX. Con los Hooks, tienen memoria (estado) y pueden reaccionar a cambios (efectos).

❌ Antes (clases)
class Counter extends React.Component {
  state = { count: 0 };
  render() { ... }
}
✅ Ahora (hooks)
function Counter() {
  const [count, setCount] = useState(0);
  return ...;
}
📌 3 cosas que recordar siempre 1) Los hooks empiezan con use. 2) Solo se llaman en el nivel superior del componente. 3) Solo dentro de componentes o de otros custom hooks.
01
useState — Estado local
El hook más fundamental. Permite a un componente "recordar" valores entre renders y volver a renderizar cuando esos valores cambian.
1 Importa useState
2 Declara [valor, setValor]
3 Lee valor en JSX
4 Llama setValor para actualizar
Demo en vivo
JSX · Counter.jsx 
import { useState } from 'react';

function Counter() {
  // [valor actual, función para cambiarlo] = useState(valor inicial)
  const [count, setCount] = useState(0);

  return (
    <div>
      <h2>Contador: {count}</h2>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={() => setCount(count - 1)}>-1</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}
💡 Cómo funciona Cuando llamas a setCount, React vuelve a ejecutar tu función componente. La línea useState(0) ya no devuelve 0, sino el último valor guardado.
Demo en vivo
JSX · Saludo.jsx 
function Saludo() {
  const [nombre, setNombre] = useState('');

  return (
    <div>
      <input
        value={nombre}
        onChange={(e) => setNombre(e.target.value)}
        placeholder="Tu nombre"
      />
      <p>Hola, <strong>{nombre || 'desconocido'}</strong> 👋</p>
    </div>
  );
}
📝 Inputs controlados El value del input lo controla React. Cada tecla dispara onChange → setNombre → re-render.
Demo en vivo
JSX · UserProfile.jsx 
function UserProfile() {
  const [user, setUser] = useState({
    name: '',
    level: 1,
    description: ''
  });

  // IMPORTANTE: nunca mutes el objeto. Crea uno nuevo con spread (...)
  const updateName = (e) => {
    setUser({ ...user, name: e.target.value });
  };

  return (
    <div>
      <input value={user.name} onChange={updateName} />
      <input
        type="number" value={user.level}
        onChange={(e) => setUser({ ...user, level: Number(e.target.value) })}
      />
      <pre>{JSON.stringify(user, null, 2)}</pre>
    </div>
  );
}
⚠️ Inmutabilidad React compara por referencia. Si haces user.name = 'x', React no detecta el cambio. Usa siempre { ...user, name: 'x' }.
Demo en vivo · Lista de tareas
JSX · TodoList.jsx 
function TodoList() {
  const [items, setItems] = useState([]);
  const [text, setText] = useState('');

  const addItem = () => {
    if (!text.trim()) return;
    setItems([...items, { id: Date.now(), text }]);
    setText('');
  };

  const removeItem = (id) =>
    setItems(items.filter(item => item.id !== id));

  return (
    <div>
      <input value={text} onChange={e => setText(e.target.value)} />
      <button onClick={addItem}>Agregar</button>
      <ul>
        {items.map(item => (
          <li key={item.id}>
            {item.text}
            <button onClick={() => removeItem(item.id)}>✕</button>
          </li>
        ))}
      </ul>
    </div>
  );
}
🔑 La prop key Cada elemento de una lista necesita una key única y estable. React la usa para identificar qué cambió, se agregó o se eliminó.
02
useEffect — Efectos secundarios
Para todo lo que sucede "fuera" del render: llamadas a APIs, suscripciones, timers, manipulación del DOM. Se ejecuta DESPUÉS de que React pinta el componente.
Demo en vivo · El título de la pestaña cambia
👆 Mira la pestaña del navegador mientras presionas los botones.
JSX · TitleEffect.jsx 
import { useState, useEffect } from 'react';

function TitleEffect() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    document.title = `Clicks: ${count}`;
  }, [count]); // se ejecuta cada vez que count cambia

  return <button onClick={() => setCount(count + 1)}>+1</button>;
}
Las 3 formas del array de dependencias
Sintaxis¿Cuándo se ejecuta?Uso típico
[ ] UNA vez, al montar el componente Cargar datos iniciales, suscribirse a eventos
[var] Cada vez que var cambia Refetch cuando cambia un id, sincronizar
(sin array) En CADA render Casi nunca — suele causar bugs
JSX · Ejemplos de dependencias 
// 1) Solo al montar
useEffect(() => {
  console.log('Componente montado');
}, []);

// 2) Cuando userId cambia
useEffect(() => {
  fetch(`/api/usuario/${userId}`)
    .then(r => r.json())
    .then(setUser);
}, [userId]);

// 3) En cada render (¡cuidado!)
useEffect(() => {
  console.log('Render');
});
Demo en vivo · Carga datos de una API real
JSX · UserList.jsx 
function UserList() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    fetch('https://jsonplaceholder.typicode.com/users')
      .then(res => {
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        return res.json();
      })
      .then(data => setUsers(data))
      .catch(err => setError(err.message))
      .finally(() => setLoading(false));
  }, []); // [] = solo al montar

  if (loading) return <p>Cargando...</p>;
  if (error)   return <p>Error: {error}</p>;

  return (
    <ul>
      {users.map(u => <li key={u.id}>{u.name}</li>)}
    </ul>
  );
}
⚠️ Patrón clásico: 3 estados Casi todo fetch necesita data, loading y error. Maneja siempre los 3 para una mejor UX.
Demo en vivo · Cronómetro con limpieza
JSX · Clock.jsx 
function Clock() {
  const [time, setTime] = useState(new Date());

  useEffect(() => {
    const id = setInterval(() => {
      setTime(new Date());
    }, 1000);

    // 🧹 CLEANUP: se ejecuta al desmontar
    // (o antes del próximo efecto)
    return () => clearInterval(id);
  }, []);

  return <h2>{time.toLocaleTimeString()}</h2>;
}
🚨 Sin cleanup = memory leak Si no limpias intervalos, suscripciones o listeners, seguirán ejecutándose después de que el componente desaparezca. Siempre devuelve una función de limpieza.
03
useContext — Estado compartido
Comparte datos entre componentes sin pasar props por cada nivel ("prop drilling"). Ideal para temas, autenticación, idioma, etc.
Prop drilling: pasar props por muchos niveles 
App (tiene user)
  └─ Layout (recibe user, lo pasa)
      └─ Sidebar (recibe user, lo pasa)
          └─ UserBadge (¡por fin lo usa!)  😩

Layout y Sidebar no necesitan user, solo lo pasan. Es código repetitivo y frágil.

JSX · 3 pasos para usar Context 
import { createContext, useContext, useState } from 'react';

// 1️⃣ Crear el contexto (puede vivir en su propio archivo)
const AuthContext = createContext(null);

// 2️⃣ Proveer el valor desde un componente padre
function App() {
  const [user, setUser] = useState({ name: 'Ana' });

  return (
    <AuthContext.Provider value={{ user, setUser }}>
      <Layout />
    </AuthContext.Provider>
  );
}

// 3️⃣ Consumir el valor en CUALQUIER hijo (sin props)
function UserBadge() {
  const { user } = useContext(AuthContext);
  return <p>Hola, {user.name}</p>;
}
🔌 Analogía con Express Es como un middleware req.user: el dato está disponible "en el aire" para cualquier ruta/componente, sin tener que pasarlo manualmente.
Demo en vivo · Compartir tema entre componentes
JSX · ThemeApp.jsx 
const ThemeContext = createContext();

function ThemeApp() {
  const [theme, setTheme] = useState('light');
  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <Toolbar />
      <Content />
    </ThemeContext.Provider>
  );
}

function Toolbar() {
  const { theme, setTheme } = useContext(ThemeContext);
  return (
    <button onClick={() => setTheme(theme === 'light' ? 'dark' : 'light')}>
      Cambiar a {theme === 'light' ? 'oscuro' : 'claro'}
    </button>
  );
}

function Content() {
  const { theme } = useContext(ThemeContext);
  return <div className={`box-${theme}`}>Tema actual: {theme}</div>;
}
04
useRef — Referencias persistentes
Caja mutable que persiste entre renders pero NO causa re-render al cambiar. Dos usos principales: acceder al DOM y guardar valores "en silencio".
Demo en vivo · Enfocar input al hacer click
JSX · SearchInput.jsx 
import { useRef } from 'react';

function SearchInput() {
  // 1) Crear la referencia
  const inputRef = useRef(null);

  const handleClick = () => {
    // 3) Acceder al DOM con .current
    inputRef.current.focus();
  };

  return (
    <div>
      {/* 2) Conectar la ref al elemento */}
      <input ref={inputRef} placeholder="Buscar..." />
      <button onClick={handleClick}>Enfocar</button>
    </div>
  );
}
Demo en vivo · Cronómetro con interval guardado en ref
JSX · StopWatch.jsx 
function StopWatch() {
  const [time, setTime] = useState(0);
  const intervalRef = useRef(null);

  const start = () => {
    if (intervalRef.current) return;
    intervalRef.current = setInterval(() => {
      setTime(t => t + 1);
    }, 1000);
  };

  const stop = () => {
    clearInterval(intervalRef.current);
    intervalRef.current = null;
  };

  return (
    <div>
      <p>Tiempo: {time}s</p>
      <button onClick={start}>Iniciar</button>
      <button onClick={stop}>Detener</button>
    </div>
  );
}

05
useReducer — Estado complejo
Alternativa a useState para estado con muchas formas de actualización. Inspirado en Redux: (state, action) → newState.
Demo en vivo · Contador con múltiples acciones
JSX · Counter con useReducer 
import { useReducer } from 'react';

// 1) Función reductora: recibe estado y acción, devuelve nuevo estado
function reducer(state, action) {
  switch (action.type) {
    case 'increment': return { count: state.count + 1 };
    case 'decrement': return { count: state.count - 1 };
    case 'add':       return { count: state.count + action.payload };
    case 'reset':     return { count: 0 };
    default:           return state;
  }
}

function Counter() {
  // 2) useReducer(reductor, estado inicial)
  const [state, dispatch] = useReducer(reducer, { count: 0 });

  return (
    <div>
      <h2>{state.count}</h2>
      {/* 3) dispatch envía una "acción" al reducer */}
      <button onClick={() => dispatch({ type: 'increment' })}>+1</button>
      <button onClick={() => dispatch({ type: 'decrement' })}>-1</button>
      <button onClick={() => dispatch({ type: 'add', payload: 10 })}>+10</button>
      <button onClick={() => dispatch({ type: 'reset' })}>Reset</button>
    </div>
  );
}
Usa useState cuando...Usa useReducer cuando...
Estado simple (string, number, boolean)Estado complejo (objeto con muchos campos)
1-2 formas de actualizarMuchas acciones distintas
Lógica de actualización trivialLógica con condiciones, validaciones
El siguiente estado no depende del anteriorEl siguiente estado depende del actual + acción
06
useMemo y useCallback — Optimización
Hooks de "memorización". Evitan recalcular valores costosos o re-crear funciones en cada render. No los uses por defecto: solo cuando hay un problema medible de rendimiento.
JSX · useMemo memoriza VALORES 
import { useMemo, useState } from 'react';

function UserStats({ users }) {
  const [filter, setFilter] = useState('');

  // Sin useMemo: este cálculo corre en CADA render (también al escribir el filtro)
  // Con useMemo: solo se recalcula si `users` cambia
  const avgLevel = useMemo(() => {
    console.log('Calculando promedio...');
    return users.reduce((sum, u) => sum + u.level, 0) / users.length;
  }, [users]); // 👈 array de dependencias

  return (
    <div>
      <p>Nivel promedio: {avgLevel}</p>
      <input value={filter} onChange={e => setFilter(e.target.value)} />
    </div>
  );
}
JSX · useCallback memoriza FUNCIONES 
import { useCallback, useState } from 'react';

function UserManager() {
  const [users, setUsers] = useState([]);

  // Sin useCallback: se crea una NUEVA función en cada render
  // → los hijos memoizados se re-renderizan innecesariamente
  const deleteUser = useCallback((id) => {
    setUsers(prev => prev.filter(u => u.id !== id));
  }, []); // 👈 sin deps → la misma función para siempre

  return (
    <ul>
      {users.map(user => (
        <UserItem key={user.id} user={user} onDelete={deleteUser} />
      ))}
    </ul>
  );
}
🤔 Regla práctica useMemo(() => fn(), deps) ≈ useCallback(fn, deps). El primero memoriza el resultado; el segundo memoriza la función misma.

07
Custom Hooks — Reutilizar lógica
Una función JavaScript cuyo nombre empieza con use y que usa otros hooks dentro. Permite extraer lógica con estado para compartirla entre componentes.
JSX · hooks/useFetch.js 
import { useState, useEffect } from 'react';

function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    setLoading(true);
    fetch(url)
      .then(res => {
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        return res.json();
      })
      .then(setData)
      .catch(err => setError(err.message))
      .finally(() => setLoading(false));
  }, [url]);

  return { data, loading, error };
}

export default useFetch;

// ✨ Uso en cualquier componente:
// const { data, loading, error } = useFetch('/api/usuarios');
♻️ Reutilización limpia Toda la lógica de fetch + loading + error queda en una sola función. Cualquier componente la usa con una línea.
JSX · hooks/useToggle.js 
import { useState, useCallback } from 'react';

function useToggle(initial = false) {
  const [value, setValue] = useState(initial);
  const toggle = useCallback(() => setValue(v => !v), []);
  return [value, toggle];
}

// Uso:
function Modal() {
  const [isOpen, toggle] = useToggle(false);

  return (
    <>
      <button onClick={toggle}>{isOpen ? 'Cerrar' : 'Abrir'}</button>
      {isOpen && <div>Modal abierto</div>}
    </>
  );
}

Reglas de los Hooks
React garantiza el orden y el estado de los hooks gracias a estas 3 reglas. Romperlas causa bugs muy difíciles de detectar.
✅ Regla 1 — Solo en el nivel superior Nunca llames hooks dentro de if, for, funciones anidadas o después de un return condicional.
✅ Regla 2 — Solo desde React Llama hooks dentro de componentes funcionales o de otros custom hooks. Nunca desde funciones normales de JavaScript.
✅ Regla 3 — El nombre empieza con use Esta convención permite que las herramientas (ESLint, React DevTools) detecten violaciones automáticamente.
JSX · Correcto vs Incorrecto 
// ✅ CORRECTO — todos los hooks en el nivel superior
function UserList({ loggedIn }) {
  const [users, setUsers] = useState([]);
  useEffect(() => { /* ... */ }, []);

  if (!loggedIn) return <p>Inicia sesión</p>;
  return <ul>...</ul>;
}

// ❌ INCORRECTO — hook dentro de un if
function UserList({ loggedIn }) {
  if (loggedIn) {
    const [users, setUsers] = useState([]); // 💥 ERROR
  }
  return <ul>...</ul>;
}

// ❌ INCORRECTO — hook después de un return
function UserList({ loggedIn }) {
  if (!loggedIn) return null;
  const [users, setUsers] = useState([]); // 💥 ERROR
  return <ul>...</ul>;
}
🛠️ Tip: instala el plugin de ESLint eslint-plugin-react-hooks detecta automáticamente estas violaciones. Viene preconfigurado en Vite y Create React App.
