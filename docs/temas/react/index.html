¿Qué es React?

  • Biblioteca JavaScript para construir interfaces de usuario
  • Basado en componentes reutilizables
  • Utiliza un DOM virtual para mejor rendimiento
  • Mantiene un flujo de datos unidireccional
  • Usa componentes funcionales (funciones de JS)

¿Por qué React?

  • Biblioteca más popular para frontend (2024-2026)
  • Usado por Meta, Netflix, Airbnb, Uber
  • Gran ecosistema y comunidad
  • Se integra directamente con sus APIs de Express

DOM Virtual

La clave del rendimiento de React

  • React mantiene una copia ligera del DOM en memoria
  • Cuando el estado cambia, compara el DOM virtual con el real
  • Solo actualiza los nodos que realmente cambiaron
  • Mucho más rápido que manipular el DOM directamente

Componentes Funcionales

La forma moderna de escribir React

Un componente = Una función

function Saludo({ nombre }) {
  return (
    <div>
      <h1>Hola, {nombre}!</h1>
      <p>Bienvenido a React</p>
    </div>
  );
}

Comparación con Express

// Express: una ruta es una función que responde
app.get('/saludo/:nombre', (req, res) => {
  res.json({ mensaje: `Hola, ${req.params.nombre}` });
});

// React: un componente es una función que retorna UI
function Saludo({ nombre }) {
  return <h1>Hola, {nombre}!</h1>;
}

En ambos casos: reciben datos → retornan algo

Props

Datos que un componente padre pasa a un hijo

// Props = parámetros del componente
function UserCard({ name, level, description }) {
  return (
    <div className="card">
      <h3>{name}</h3>
      <p>{description}</p>
      <span>Nivel: {level}</span>
    </div>
  );
}

// Uso del componente
<UserCard name="Luis" level={90} description="Jugador" />

Analogía con Express

// En Express, req.body son los "props" de una ruta
app.post('/usuario', (req, res) => {
  const { name, level, description } = req.body;
  // ...
});

// En React, props son los datos que recibe el componente
function UserCard({ name, level, description }) {
  // ...
}

Estado (State)

Datos internos que el componente puede cambiar

useState: el hook básico de estado

import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Contador: {count}</p>
      <button onClick={() => setCount(count + 1)}>
        Incrementar
      </button>
    </div>
  );
}

Props vs Estado

Props Estado
Vienen del padre Son internos
Son de solo lectura Se pueden modificar
El hijo NO los cambia El componente los actualiza

React + Express

Consumiendo sus APIs desde React

fetch() para conectar con el backend

import { useState, useEffect } from 'react';

function UserList() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetch('http://localhost:3001/usuarios')
      .then(res => res.json())
      .then(data => {
        setUsers(data);
        setLoading(false);
      });
  }, []);

  if (loading) return <p>Cargando...</p>;

  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}

Crear usuarios desde React

function CreateUser() {
  const [name, setName] = useState('');
  const [level, setLevel] = useState(1);

  const handleSubmit = async (e) => {
    e.preventDefault();
    await fetch('http://localhost:3001/usuario', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ name, level })
    });
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={name}
        onChange={e => setName(e.target.value)}
        placeholder="Nombre"
      />
      <button type="submit">Crear</button>
    </form>
  );
}

Errores Comunes

Lo que van a encontrar al conectar React con Express

1. CORS Error

Access to fetch at 'http://localhost:3001/usuarios'
from origin 'http://localhost:5173' has been blocked
by CORS policy

Solución: Instalar y usar cors en Express

// En el backend
const cors = require('cors');
app.use(cors());

2. Cannot read properties of undefined

// ❌ Error: users es undefined antes de que cargue
function App() {
  const [users, setUsers] = useState(); // sin valor inicial
  return <p>{users.length}</p>; // 💥 crash
}

// ✅ Solución: siempre inicializar con valor correcto
function App() {
  const [users, setUsers] = useState([]); // array vacío
  return <p>{users.length}</p>; // 0, sin crash
}

3. useEffect loop infinito

// ❌ Error: se ejecuta infinitamente
useEffect(() => {
  fetch('/api/users').then(r => r.json()).then(setUsers);
}); // ← Falta el array de dependencias!

// ✅ Solución: agregar [] para ejecutar solo al montar
useEffect(() => {
  fetch('/api/users').then(r => r.json()).then(setUsers);
}, []); // ← Se ejecuta UNA vez

4. No manejar loading state

// ❌ El usuario ve una página vacía mientras carga
function App() {
  const [users, setUsers] = useState([]);
  useEffect(() => { /* fetch... */ }, []);
  return <ul>{users.map(...)}</ul>; // vacío 1-2 seg
}

// ✅ Mostrar indicador de carga
function App() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  // ...
  if (loading) return <p>Cargando...</p>;
  return <ul>{users.map(...)}</ul>;
}

5. Olvidar Content-Type en POST

// ❌ Express recibe req.body = undefined
await fetch('/api/usuario', {
  method: 'POST',
  body: JSON.stringify({ name: 'Luis' })
});

// ✅ Agregar el header Content-Type
await fetch('/api/usuario', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'Luis' })
});
